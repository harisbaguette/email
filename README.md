# Mailroom

`@bluekite.co.kr`로 오는 메일을 [email.bluekite.co.kr](https://email.bluekite.co.kr)에서 읽는 개인 수신함입니다.

- **설정 → 이메일 주소 → 새 주소 → 만들고 복사**를 누르면 바로 쓸 주소가 준비됩니다. 자동으로 채운 이름을 `pixiv`처럼 바꿔도 됩니다. 등록하지 않은 주소의 메일은 거절합니다.
- 기본 화면은 **안 읽은 메일**입니다. 상단 설정 옆의 메일함 메뉴에서 받은 메일 전체나 다른 메일함으로 이동합니다.
- 모든 주소의 메일을 하나의 수신함에서 확인합니다. 인증번호는 목록에서 바로 복사할 수 있습니다.
- 인증 메일을 열면 인증번호와 확인 링크가 본문 위에 나타납니다. 확인 링크에는 열릴 도메인이 함께 표시됩니다. 보낸 주소와 다른 도메인으로 이동할 때는 주소를 한 번 더 확인합니다.
- 광고, 뉴스레터, 스팸은 **광고와 소식**으로 자동 정리합니다. 인증, 결제, 보안 메일과 판단이 애매한 메일은 받은 메일에 남깁니다. 잘못 분류된 메일은 열어서 **더보기(⋯) → 광고 아님** 또는 **광고와 소식으로 이동**을 누릅니다. 직접 옮긴 메일은 자동으로 다시 옮기지 않습니다.
- 메일함 이름을 누르면 인증 메일, 별표, 보관함, 광고와 소식, 전체 메일, 휴지통으로 이동합니다. 광고함도 자동 삭제하지 않습니다.
- **설정 → 이메일 주소**를 열면 기존 주소를 복사할 수 있습니다. 주소 옆 화살표는 해당 주소의 메일을 보여줍니다.
- 제목, 보낸 사람, 받는 주소, 본문으로 검색할 수 있습니다. **상세 검색**에서는 발신자·수신 주소·날짜·첨부 파일로 좁힙니다. `from:`, `to:`, `subject:`, `after:`, `before:`, `has:attachment`, `is:unread`를 검색창에 직접 써도 됩니다.
- 목록의 **메일 선택**에서 최대 100통을 읽음·별표·보관·휴지통으로 한 번에 정리합니다. 휴지통 이동과 보관은 바로 되돌릴 수 있습니다.
- **설정 → 자동 정리**에서 발신자별 이동 규칙을 등록합니다. 새로 도착하는 메일에 적용하며 기존 메일은 그대로 둡니다.
- 주소에 메모를 붙이거나 목록에서 숨길 수 있습니다. **수신 중지**는 새 메일을 거절하며 기존 메일은 남깁니다. 중지된 주소를 사용하려면 **주소 설정 → 다시 수신**을 누릅니다.
- 첨부 파일과 `.eml` 원본을 내려받을 수 있습니다.
- 메일과 주소는 자동 삭제하지 않습니다. 휴지통의 메일도 직접 영구 삭제하기 전까지 보관합니다.
- 외부 이미지는 기본으로 차단합니다. 필요한 메일에서 **외부 이미지 표시**를 누르면 불러옵니다.

수신 전용입니다. 메일 한 통은 첨부를 포함해 10 MiB까지 받습니다. 긴 본문은 화면에서 일부만 표시하며 전체 내용은 원본 파일에 보관합니다. 서버는 Cloudflare Workers와 D1을 사용하며 Gmail이나 네이버로 전달하지 않습니다.

대량 수신 보호 한도는 주소당 분당 20통·시간당 120통, 전체 분당 60통·시간당 300통·24시간 동안 1,000통입니다. 전체 수신 용량은 분당 30 MiB·시간당 75 MiB·24시간 동안 100 MiB로 제한합니다. 보관 한도는 256 MiB 또는 20,000통입니다. 한도를 넘는 새 메일은 수신을 거절합니다. 시간 제한이 풀리거나 보관 공간을 확보한 뒤 필요한 메일을 다시 요청하세요. 이미 보관한 메일은 지우지 않습니다.

## 로그인

설정한 아이디와 비밀번호로 로그인합니다. 이 컴퓨터의 `.local/접속정보.txt`에도 접속 정보가 있습니다. 비밀번호는 **설정 → 계정 → 비밀번호 변경**에서 바꿀 수 있습니다.

**설정 → 계정 → 로그인한 기기**에서 다른 기기를 로그아웃할 수 있습니다. 해당 기기의 알림도 함께 해제됩니다.

**설정 → 계정 → 2단계 인증**에서 인증 앱을 연결할 수 있습니다. QR 코드를 등록하고 복구 코드를 안전한 곳에 저장한 뒤 인증 앱의 6자리 코드를 입력하면 켜집니다. 이후 로그인과 비밀번호 변경에는 인증 앱 코드 또는 일회용 복구 코드가 필요합니다. 설정하거나 해제하면 다른 기기의 로그인과 모든 알림 연결이 해제됩니다.

## 앱으로 설치

Chrome 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 선택합니다. 아이폰은 Safari의 공유 메뉴에서 **홈 화면에 추가**를 선택합니다. 브라우저를 여는 것만으로 자동 설치되지는 않습니다.

설치 후 홈 화면의 Mailroom 아이콘으로 수신함을 엽니다. 메일 확인에는 인터넷 연결이 필요하며 메일 본문과 첨부 파일은 오프라인 캐시에 저장하지 않습니다.

## 모바일 알림

**설정 → 알림 → 켜기**를 누르고 브라우저에서 알림을 허용합니다. 각 기기에서 한 번씩 연결합니다. 아이폰은 iOS 16.4 이상에서 홈 화면에 추가한 앱으로 열어야 합니다.

기본으로 인증 메일만 알립니다. **받은 메일 전체**로 바꾸면 광고함을 제외한 메일도 알려줍니다. 잠금 화면의 보낸 사람과 제목은 **내용 미리보기**를 켠 경우에만 표시합니다. 알림을 누르면 해당 메일이 열립니다. 기기의 알림 차단이나 집중 모드에 따라 표시가 늦어질 수 있습니다.

로그아웃하거나 로그인 세션이 만료되면 해당 기기의 알림이 해제됩니다. **다른 알림 기기**에서는 연결을 개별 해제할 수 있습니다. 비밀번호를 바꾸면 모든 기기의 알림을 다시 연결해야 합니다. 연결 상태는 **알림 보내기**로 확인합니다.

서버의 웹 푸시 서명 키는 Worker의 `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` secret에 보관합니다. 키를 교체하면 기존 기기의 알림을 다시 연결해야 합니다. 로컬 알림 검사에도 `.dev.vars`에 이 두 값이 필요합니다.

## 비밀번호 재설정

비밀번호를 잊었을 때는 Cloudflare 계정에 로그인한 컴퓨터에서 다음 명령을 실행합니다. 새 비밀번호가 같은 파일에 저장되고 기존 로그인은 모두 해제됩니다.

```sh
npm run password:reset
```

인증 앱과 복구 코드도 모두 잃어버린 경우에만 다음 명령으로 2단계 인증을 함께 해제합니다.

```sh
npm run password:reset -- --disable-two-factor
```

## 로컬 실행

Node.js 22.18 이상이 필요합니다.

```sh
npm ci
npm run db:local
npm run password:local
npm run dev
```

`http://127.0.0.1:8787`에서 열고 `.local/local-access.json`의 아이디와 비밀번호로 로그인합니다. 로컬 메일과 운영 메일은 분리됩니다. 화면 개발 중에는 다른 터미널에서 `npm run dev:ui`를 실행해 Vite를 사용할 수 있습니다.

```sh
npm test
npm run test:e2e
```

브라우저가 없는 환경에서는 먼저 `npx playwright install chromium firefox webkit`을 실행합니다. 브라우저 검사는 빠진 로컬 인증·알림 시험 키를 `.dev.vars`에 만들고 로컬 로그인 비밀번호를 재설정합니다. 검사 중 만든 메일과 주소는 종료 시 삭제합니다.

## UI 수정

공통 컴포넌트의 선택과 사용법은 [디자인 시스템](DESIGN_SYSTEM.md)에 있습니다. `npm run check`로 UI 규칙·서버·빌드를 검사하고 `npm run test:e2e`로 화면을 확인합니다.

## 배포

Cloudflare 계정과 도메인, D1 연결은 `wrangler.jsonc`에 있습니다.

```sh
npx wrangler login
npm run deploy
```

GitHub에 푸시하는 것만으로 운영 사이트가 갱신되지는 않습니다. `npm run deploy`가 데이터베이스 마이그레이션과 화면과 Worker 배포를 수행합니다. 기존 메일과 비밀번호는 유지합니다.

Email Routing의 `*@bluekite.co.kr` catch-all을 `bluekite-mail` Worker로 연결해야 메일이 도착합니다. DNS의 MX 레코드는 Cloudflare Email Routing이 관리합니다. 같은 도메인에 다른 메일 서비스를 연결하면 수신 경로가 달라질 수 있습니다.

데이터베이스에는 메일 본문과 압축한 원본이 함께 들어 있습니다. 별도 백업은 다음 명령으로 만들 수 있습니다. 백업 파일에는 개인 메일이 포함되므로 공개 저장소에 올리지 마세요.

```sh
npx wrangler d1 export bluekite-mail --remote --output .local/backup.sql
```

Cloudflare 요금제의 Workers와 D1 사용량과 저장 한도가 적용됩니다. D1이 가득 차거나 한도를 넘으면 새 메일 저장이 실패할 수 있습니다. 설정 화면에서 보관 중인 메일의 용량을 확인할 수 있습니다.

2단계 인증의 설정 키는 `MFA_ENCRYPTION_KEY`로 암호화해 저장합니다. 다른 환경에서는 무작위 32바이트를 Base64로 인코딩한 값을 Worker secret에 등록하고 로컬 `.dev.vars`에도 설정합니다. 키를 잃어버리면 기존 인증 앱 코드를 확인할 수 없으므로 안전하게 별도 보관해야 합니다. 운영 키를 교체할 때는 기존 2단계 인증을 먼저 해제하고 다시 등록하세요.

## 광고 자동 정리

Jev API 키는 Worker의 `TYPESAFE_API_KEY` secret에 보관합니다. 다른 환경에 설치할 때는 `npx wrangler secret put TYPESAFE_API_KEY`로 등록합니다. 로컬에서도 분류하려면 Git에서 제외된 `.dev.vars`에 같은 이름으로 넣습니다.

분류에는 제목과 본문 일부만 보냅니다. 링크, 이메일 주소, 긴 숫자, 긴 토큰은 가리고 첨부 파일은 보내지 않습니다. 인식된 인증번호나 인증 링크가 있는 메일은 외부 분류 없이 받은 메일에 남깁니다. 데이터 처리 조건은 [TypeSafe 안내](https://docs.typesafe.ai/legal)를 확인하세요.

메일을 먼저 저장한 뒤 분류하므로 분류 장애 때문에 수신이 실패하지 않습니다. 기존 메일과 재시도할 메일은 5분마다 정리합니다. 요청은 하루 500회까지이며 초과분은 다음 날 처리합니다. 분류가 지연되면 설정의 계정 화면에 표시하고 받은 메일에 보관합니다. Jev 사용료는 [모델 요금](https://docs.typesafe.ai/models)에 따라 기존 계정에 적용됩니다.

분류 기준을 바꾸려면 `worker/sorting-policy.ts`를 수정합니다. 가상 메일로 실제 API를 시험하려면 `TYPESAFE_API_KEY` 환경변수를 설정한 뒤 `node --experimental-strip-types scripts/evaluate-sorting.mjs`를 실행합니다. 이 검사는 실제 API 사용량을 발생시킵니다.
